## 1. Requirements & Constraints

- **REQ-001 — Complete means end to end:** The approved deployed slice must support target selection → eligible candidate inspection → explicit manual selection → unit-correct comparison → selected-context chat with resolvable evidence → reset/change without stale state. A dataset, notebook, mock screen, or successful chat call alone does not satisfy completion.
- **REQ-002 — Mandatory analytical path:** Every browser analytical operation follows `browser → ACA application orchestrator → Foundry → authenticated fixed MCP relay → Fabric Data Agent → approved serving views`. No browser SQL, backend SQL/Delta/CSV queries, parallel analytical agent, direct semantic API shortcut, or silent local/mock fallback. Offline test oracles are not runtime data sources.
- **REQ-003 — Separate planned from observed:** Targets retain expected formation, planned hole size/MD range/trajectory, coordinate frame, reference-release metadata, and `PLANNED_TARGET`. They have no realized footage/duration/run outcomes and never enter historical counts, quality totals, splits, or training data. A target's `reference_dataset_version=v1.0.0` is provenance, not permission to join to v1.0.0 history.
- **REQ-004 — Transparent eligibility:** Apply supported predicates at a matching historical section before aggregating comparisons. Return distance, applied criteria, matching section count, warning/quarantine coverage, and explicit reasons for exclusion/unavailable values. Candidate order is distance ascending, then `well_id`; call it proximity ordering, never similarity ranking.
- **REQ-005 — Distance semantics:** Require identical coordinate frame, `ft` units, surface semantics, and finite coordinates. Use `distance_squared_ft2 = (target_x_ft-well_x_ft)^2 + (target_y_ft-well_y_ft)^2`. Eligibility uses `distance_squared_ft2 <= radius_ft^2` before rounding; displayed distance is its square root rounded to one decimal foot. No lat/lon, map/geodetic orientation, subsurface distance, geological equivalence, or trajectory inference.
- **REQ-006 — Release-safe joins:** Pin `releaseId=v1.1.0:904a5b293fdf0654fb1c5b4d28dd79d1c9cfaaac612f71d8f297ec874f4d284d`, dataset version, manifest hash, transformation-contract version, and query-contract version. All joins include `_release_id` and entity keys; run-to-section joins also validate `well_id`. Never join releases by well/section/run IDs alone. Preserve the immutable v1.0.0 files and rollback products.
- **REQ-007 — Grain and quality:** Derive selected comparisons from accepted `PASS`/`WARNING` runs, retain warnings, exclude `ERROR` runs from performance metrics, and expose excluded counts separately. Aggregate runs to section, then matching sections to well; join issue counts only after deduplication at their declared grain. Do not average averages, multiply totals by target/section joins, or describe source totals as accepted totals.
- **REQ-008 — Metrics:** For each selected well show matching accepted run count, accepted footage `ft`, accepted duration `hours`, average accepted footage/run `ft/run = SUM(footage_ft)/COUNT(accepted runs)`, and historical summary penetration rate `ft/hour = SUM(footage_ft)/SUM(duration_hours)`. Label the latter as a ratio of recorded summary quantities, not instantaneous ROP. Also show matching section count, quarantined run count, and warning counts. No target outcome, predicted delta, or engineering recommendation.
- **REQ-009 — Nulls and intervals:** Preserve unknown formation/trajectory as unknown, not zero or inferred text. `UNKNOWN` normalization is a display state, not an actual matching formation. Zero accepted runs gives null performance metrics and ineligibility; zero/nonpositive duration gives null rate and a data-quality failure, not infinity. Optional MD overlap uses `max(section_start,planned_min) < min(section_end,planned_max)`; touching endpoints do not overlap. If enabled, aggregate whole matching sections, label that scope, and do not prorate outcomes to the overlap.
- **REQ-010 — Evidence:** Each analytical payload and material chat claim must resolve to authorized serving view/columns or semantic measures, actual authenticated tool result, release/hash, target, filters, selected IDs, metric grain, units, and a safe query/receipt ID. Neither model-authored `totalCount`/`truncated`/echoed context nor a successful `mcp_call`/decorative source name establishes authority or completeness. Prove server-owned request→tool-call→result correlation in TASK-026/028; compare full candidate IDs, row count, uniqueness, metrics and contexts to the independent oracle. Preserve the existing exact v1.0.0 label for legacy responses; approve a version-bound offset label before use.
- **SEC-001 — Preserve identity boundary:** Anonymous POC browsing does not grant Fabric rights. Keep service managed identity, fixed relay target, tenant/audience/signature/lifetime/role/principal checks, HTTPS, redacted telemetry, kill switch, and current single-replica request quotas. Extend quota accounting to target/candidate/compare operations; each upstream attempt must be bounded and accounted for. No credentials in source/evidence and no caller-selected endpoints, SQL, or query templates.
- **SEC-002 — Minimize exposure:** Only approved serving summaries may be exposed. Do not expose raw/curated/control/physical tables, individual runs, hidden prompts, tokens, or unrestricted exports. Proposed POC has no downloadable export; copying the bounded visible comparison is not authorization for bulk extraction. Thomas must approve any widened public source/field scope and reconfirm existing network exceptions; this plan does not assert production network isolation.
- **CON-001 — Planning-only now:** No source/state edits, agent reactivation, Git operations that alter state, cloud API calls, capacity resume, deployment, or commit are authorized by this document. All tasks below are future gated work.
- **CON-002 — Existing resources only:** Future approved operations use workspace `4e1977a8-d7ff-487e-b42d-c4b3bc118f3d`, Lakehouse `964afbf5-6a33-46dc-98c1-be726d0f4999`, and existing F8. Raw prefix is `Files/landing/synthetic/drill_run/v1.1.0/`. No new capacity, new infrastructure, ML dependencies, similarity score, prediction, optimization, or real-well accuracy claims.
- **CON-003 — Baseline/review first:** Preserve dirty user changes. Establish an explicitly approved local source baseline and distribution/recovery strategy; no remote exists, so do not imply remote review/CI or create a remote without approval. ## 7. Risks & Assumptions

- **RISK-001 — Governance drift:** Root README and roster describe superseded SWA/Functions or Fabric-only paths; current app source/app README describe ACA/Foundry. Treat actual implementation as the code baseline, but require explicit scope/routing decisions rather than treating drift as authorization.
- **RISK-002 — Free-form output/correlation:** The question-oriented tool is not a guaranteed row API; current parser supplies narrative/source summaries and relay forwards streams without evidence validation. TASK-026 may fail authenticated structure/completion/correlation proof; TASK-028 may fail full bounded numerical fidelity. Both stop production investment, while TASK-019 remains full revalidation. No model totals/context echoes, server SQL recomputation or guessed narrative numbers can clear a gate.
- **RISK-003 — Binding/effective exposure uncertainty:** Local public definition is Lakehouse based, historical docs semantic-only; zero logical `.platform` ID is not a live binding. Excluded raw/curated parent nodes retain selected descendants: this is an observed selection concern, not proof of a live breach. TASK-025 export/read-back and actual effective ACL/source gate precede broadened offset probes; unproved or excessive exposure requires separately authorized remediation/reverification. TASK-015 never waits for a TASK-019 first export.
- **RISK-004 — Aggregate inflation:** Reused IDs across releases, target pair replication, section/run/issue joins and category source-history counts can silently produce plausible wrong figures. Composite keys, preaggregation, exact predicate reuse and independent numerical oracles are hard gates.
- **RISK-005 — Planning context mistaken for geology:** Fictional local surface distance, expected formation, planned MD and descriptive trajectory do not establish subsurface comparability, regional accuracy, engineering validity or safety. UI and chat must repeat material limitations.
- **RISK-006 — Dirty/ignored baseline:** Uncommitted source and ignored release archives make reproducibility and rollback fragile. Do not rewrite manifest `source_control_status=working_tree` / `release_status=generated_unpublished` to imply retroactive provenance. Record later baseline separately.
- **RISK-007 — Cost/availability and wasted investment:** UI operations amplify Foundry/Fabric calls under process-local quotas, a 210-second upstream timeout and paused capacity. Measure amplification/latency/usage/cost at TASK-026 before substantial build work and approve TASK-028 budget; count all attempts, no per-row model fanout, auto-load-all-targets or retry loops. Retain one replica and no new infrastructure/ML. Direct-view feasibility does not wait for full semantic parity; a semantic-only choice requires a revised dependency/cost decision. No claim that the old 15-second target is achieved.
- **RISK-008 — Conversation leakage/staleness:** Existing browser localStorage and arbitrary continuation input are not context authorization. New association/capability validation, generation guards and receipt checking are necessary before selected-context chat is complete.
- **RISK-009 — Migration rollback coupling:** Schema, pointer, semantic metadata, Data Agent selection, disclosure and Foundry/app version must be compatible. Separate staging from activation and retain exact last-known-good bundle; historical Foundry v4 alone may target retired hosting.
- **RISK-010 — Review independence:** Go Gunhee rejected v1.0; Yoo Jinho independently revised v1.1 without the locked-out author, and Go Gunhee approved its sequencing on re-review. Baek accepts subsequent evidence independently; plan approval cannot substitute for capability/release evidence or override a later rejection.
